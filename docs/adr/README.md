# Architecture Decision Records (ADR)

บันทึกการตัดสินใจสำคัญ 1 เรื่องต่อ 1 ไฟล์ ตามรูปแบบ [MADR 4.0](https://adr.github.io/madr/) — ใช้กับ `/grill-with-docs` ของ Claude Code ได้ตรง ๆ (skill นั้นเขียนลง `docs/adr/` อยู่แล้ว)

## บันทึกเมื่อไร

บันทึกเฉพาะเมื่อครบทั้ง 3 ข้อ (ขาดข้อใดข้อหนึ่ง ไม่ต้องบันทึก — ใส่ไว้ใน PR description พอ):

1. **ย้อนกลับยาก** — เปลี่ยนใจทีหลังมีต้นทุนจริง
2. **ถ้าไม่บอก คนอ่านจะสงสัย** — คนหรือ agent ที่มาทีหลังจะถามว่า "ทำไมทำแบบนี้"
3. **เป็นการชั่งทางเลือกจริง** — มีทางเลือกอื่นที่ใช้ได้ และเลือกด้วยเหตุผลเฉพาะ

## กติกา

- ชื่อไฟล์ `NNNN-<slug>.md` เลขรันต่อจากไฟล์ล่าสุด 4 หลัก (`0002-auth-session.md`) slug เป็นอังกฤษตัวเล็กคั่นด้วย `-`
- เริ่มจาก `template.md` — หัวข้อที่ไม่จำเป็นลบได้ แต่ต้องมี สถานะ, บริบท, ทางเลือก, ผลการตัดสินใจ
- อ้างถึงด้วย `ADR-NNNN` (เช่น ใน PR, issue, `.trivyignore-license.yaml`)
- สถานะ: `proposed` → `accepted` | `rejected`; ภายหลัง `deprecated` หรือ `superseded by ADR-NNNN`
- **ห้ามแก้เนื้อหา ADR ที่ accepted แล้ว** (ยกเว้นคำผิด/ลิงก์) — เปลี่ยนใจให้เขียน ADR ใหม่ที่อ้างถึงอันเดิม แล้วแก้สถานะอันเดิมเป็น `superseded by ADR-NNNN`
- ADR เขียนใน PR เดียวกับโค้ดที่ทำตามการตัดสินใจนั้น และเพิ่มบรรทัดในดัชนีด้านล่าง
- เนื้อหาภาษาไทยได้ ศัพท์เทคนิคใช้อังกฤษ
